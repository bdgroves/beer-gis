📏 Data Quality · GIS Concepts

Data Quality

ISO 19157 quality elements — diagnosing errors in a Pacific Northwest brewery dataset. Four types, four beer scenarios.

Element 01

Positional Accuracy

Positional accuracy describes how closely the recorded coordinates match the true real-world location. The feature exists, it's real — it's just in the wrong place on the map.

🍺 Brewery Dataset Example
Fremont Brewing on N 34th St in Seattle is mapped two blocks east of its actual location. The brewery is real, the data is otherwise complete — but the coordinates are wrong. A delivery driver using this map would show up at the wrong address.
Causes
GPS multipath error · poor satellite geometry · digitizing from low-resolution imagery · datum mismatch (NAD 27 vs NAD 83 without transformation)
Element 02

Logical Consistency

Logical consistency describes whether features are internally consistent with each other and with real-world rules. The individual features may be in the correct locations — but together they create an impossible or contradictory situation.

🍺 Brewery Dataset Example
Reuben's Brews in the Roosevelt neighborhood is plotted inside the Green Lake polygon. A brewery cannot physically exist inside a lake. The brewery location and the lake polygon contradict each other — a logical inconsistency. Also: a parcel coded as both "commercial" and "residential" simultaneously, or a taproom whose boundary overlaps the adjacent building footprint.
Exam Triggers
"Road through a lake" · "Building inside a river" · "Bridge below the river it crosses" · "Coded as both X and Y" · "Overlapping parcels" → Logical inconsistency
Element 03

Attribute Accuracy

Attribute accuracy describes whether the values in the attribute table correctly represent the real-world characteristics of each feature. The location is right — the data about the feature is wrong.

🍺 Brewery Dataset Example
Elysian Brewing on Capitol Hill is correctly located on the map but its TYPE field reads "Winery" instead of "Brewery." The coordinates are accurate — the attribute value is wrong. A query for "all breweries" would miss Elysian entirely.
Exam Triggers
"Classified as wrong type" · "Wrong attribute value" · "Mislabeled" · "Coded incorrectly" — but the feature is in the right location → Attribute accuracy
Element 04

Temporal Accuracy

Temporal accuracy describes whether the data reflects the correct time period. The feature may have been accurately mapped at some point — but reality has changed and the data hasn't kept up.

🍺 Brewery Dataset Example
The dataset still shows the Elysian Brewing Capitol Hill taproom even though it closed in 2019. The location was accurate when collected — but the taproom no longer exists. A beer tourist using this map would find an empty storefront. Also: a brewery that rebranded two years ago still appears under its old name.
Exam Triggers
"No longer exists" · "Closed/demolished but still shown" · "Old dataset used for current study" · "Hasn't been updated to reflect recent changes" → Temporal accuracy

🍺 The Two-Question Test

1.
Is the brewery in the wrong location? → Positional accuracy
2.
Does the brewery contradict another feature or violate a real-world rule (inside a lake, inside a building)? → Logical consistency
3.
Is the brewery's attribute value wrong (classified as winery, wrong name, wrong hours)? → Attribute accuracy
4.
Is the brewery no longer open but still shown, or is the data from the wrong time period? → Temporal accuracy
